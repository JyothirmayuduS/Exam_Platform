# Moodle LTI 1.3

Vignan's Moodle can open an exam on this platform and get the score back.

- **Student:** clicks the activity in Moodle and lands on the exam already signed in as their own platform account. There is no second login.
- **Grade:** when the attempt is submitted and graded, the score goes to that activity's column in the Moodle gradebook. If Moodle is unreachable, the score is queued and retried.
- **One exam per activity:** each Moodle activity opens only the exam a teacher of that course linked it to.

Replace `<ref>` below with the Supabase project ref and `<app>` with the web app origin (for example `https://exam.vignan.ac.in`).

## Values Moodle needs

| Moodle field | Value |
| --- | --- |
| Tool URL | `https://<ref>.supabase.co/functions/v1/lti/launch` |
| LTI version | LTI 1.3 |
| Public key type | Keyset URL |
| Public keyset | `https://<ref>.supabase.co/functions/v1/lti/jwks` |
| Initiate login URL | `https://<ref>.supabase.co/functions/v1/lti/login` |
| Redirection URI(s) | `https://<ref>.supabase.co/functions/v1/lti/launch` |
| Client ID | Generated by Moodle when you save the tool (see section 2) |

## 1. Platform setup (once)

1. Create the tool's signing key and a scheduler secret, and store them as secrets:

   ```bash
   openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out lti-private.pem
   supabase secrets set LTI_PRIVATE_KEY="$(cat lti-private.pem)" LTI_KEY_ID=vignan-lti-1 \
     APP_BASE_URL=https://<app> LTI_CRON_SECRET="$(openssl rand -hex 32)"
   ```

   - Keep `lti-private.pem` out of git, and delete it after setting the secret.
   - Moodle reads the public half from the keyset URL, so there is nothing to paste into Moodle.
   - To rotate the key, set a new `LTI_PRIVATE_KEY` with a new `LTI_KEY_ID`.

2. Apply the migrations and deploy the functions:

   ```bash
   supabase db push                     # adds the lti_* tables
   supabase functions deploy lti --no-verify-jwt
   supabase functions deploy submit-attempt
   ```

   `lti` must be deployed with `--no-verify-jwt`: Moodle calls it without a Supabase session. The teacher routes check the teacher's own session inside the function.

3. Schedule grade retries every 5 minutes. Run this in the SQL editor; it needs the `pg_cron` and `pg_net` extensions:

   ```sql
   select cron.schedule('lti-grade-retry', '*/5 * * * *', $$
     select net.http_post(
       url := 'https://<ref>.supabase.co/functions/v1/lti/retry',
       headers := jsonb_build_object('x-lti-cron-secret', '<LTI_CRON_SECRET>')
     );
   $$);
   ```

   Without the schedule, queued grades are still retried a few at a time whenever any student submits. Teachers can also press **Resend grades to Moodle** at any time.

## 2. Moodle admin steps

1. Go to **Site administration → Plugins → Activity modules → External tool → Manage tools**, then choose **configure a tool manually**.
2. Fill in the tool settings:
   - **Tool name:** Vignan Exam Platform
   - **Tool URL, LTI version, Public key type, Public keyset, Initiate login URL, Redirection URI(s):** use the table above.
   - **Tool configuration usage:** Show in activity chooser and as a preconfigured tool.
   - **Default launch container:** New window. The exam and the lockdown browser hand-off need a full browser tab, not an iframe.
3. Under **Services**, set **IMS LTI Assignment and Grade Services** to **Use this service for grade sync only**.
4. Under **Privacy**:
   - **Share launcher's name with tool:** Always
   - **Share launcher's email with tool:** Always
   - **Accept grades from the tool:** Always
5. Save. In the tool list, click the **View configuration details** icon on the new tool. Moodle shows these values:
   - **Platform ID** (the issuer)
   - **Client ID**
   - **Deployment ID**
   - **Public keyset URL** (`…/mod/lti/certs.php`)
   - **Access token URL** (`…/mod/lti/token.php`)
   - **Authentication request URL** (`…/mod/lti/auth.php`)
6. Register Moodle on this platform with those values. At least one deployment id is required. Run this in the Supabase SQL editor:

   ```sql
   insert into public.lti_platforms
     (name, issuer, client_id, deployment_ids, auth_login_url, auth_token_url, jwks_url)
   values (
     'Vignan Moodle',
     'https://lms.vignan.ac.in',                       -- Platform ID
     '<Client ID>',
     array['<Deployment ID>'],
     'https://lms.vignan.ac.in/mod/lti/auth.php',       -- Authentication request URL
     'https://lms.vignan.ac.in/mod/lti/token.php',      -- Access token URL
     'https://lms.vignan.ac.in/mod/lti/certs.php'       -- Public keyset URL
   );
   ```

7. **Set every student's Moodle ID number to their roll number**, and make sure students cannot edit it. Go to **Site administration → Users → Permissions → User policies → Locked user fields** and lock **ID number**. The ID number is the only Moodle field used to match a student automatically.

## 3. How students are matched

A Moodle user becomes a platform student in one of these ways, and no other:

1. **Already linked.** Their Moodle account (issuer plus Moodle user id) was linked before. From then on only that link is used. Later changes to the ID number, email or username in Moodle have no effect.
2. **ID number.** Their Moodle ID number equals a student's roll number, and that student is not linked to another Moodle account.
3. **Confirmed by a teacher.** Anyone else is not signed in. They see "Your account is waiting for your teacher", and they appear under **Moodle students waiting to be linked** for teachers of that course. The teacher either links them to an existing roll number or adds them as a new student.

Email and username are never used for matching, because Moodle users can usually change them. Teachers see them only as hints when confirming.

An admin can pre-link accounts in bulk:

```sql
insert into public.lti_users (platform_id, sub, student_id)
select p.id, '<Moodle user id>', s.id
from public.lti_platforms p, public.students s
where p.name = 'Vignan Moodle' and s.roll = '<roll>';
```

The Moodle user id is the numeric id in the user's profile URL (`user/profile.php?id=…`).

## 4. Teacher steps: linking an activity to an exam

1. In the Moodle course, **Add an activity → External tool**, and pick **Vignan Exam Platform**.
2. Set **Maximum grade** in the activity's **Grade** section. Moodle scales our score to that maximum: 18 out of 25 on our side becomes 72 out of 100 if the maximum is 100.
3. Save, then open the activity yourself. Teachers are never signed in by a launch. The first time, click **Link my Moodle course** and sign in with your platform teacher account. This ties your Moodle teacher account to you. Each Moodle teacher account can belong to only one platform teacher.
4. On the platform, open your exam and go to **Candidates → Moodle links**. You see only activities from Moodle courses you have opened as a teacher. Click **Link to this exam**.
   - You can link an activity only to an exam you own.
   - If a colleague has already linked an activity to their exam, you cannot change it.
5. Optional safety pin: in the Moodle activity, under **Custom parameters**, add `exam_id=<exam id>`. If the activity is ever linked to a different exam, launches are refused instead of opening the wrong one.

**Roles:**

| Moodle course role | Result |
| --- | --- |
| Learner (student) | Signed in as the matched student. |
| Instructor (teacher) | Shown the teacher page; never signed in. |
| No role, any other role, or both at once | Refused with a message. |

**Where the grade goes:** the activity's own column in the Moodle gradebook (Course → Grades).

**When it is sent:**

- **Objective-only papers:** at submit.
- **Papers with written answers:** when the teacher saves the marks on the Evaluation page.
- **Re-grades:** sent again, and Moodle keeps the latest.

Submitting never waits for Moodle.

**If Moodle is down:**

- The score is queued and retried after 1, 5 and 15 minutes, then 1, 3, 6 and 12 hours, then daily.
- After 12 failed tries it stays queued until a teacher presses **Resend grades to Moodle** on the exam's **Candidates** tab.

The grade is sent as soon as it exists, whatever the platform's result-release setting is. To hold grades back from students, hide the grade item in the Moodle gradebook until you are ready.

## How a launch works

1. Moodle starts the OIDC login at `/lti/login`. The tool stores a one-time `state` and `nonce` and sends the browser back to Moodle.
2. Moodle posts a signed `id_token` to `/lti/launch`. The tool checks all of these:
   - the signature, against Moodle's keyset (fetched with a 5-second timeout);
   - the issuer, client id and a registered deployment id;
   - the expiry and the nonce;
   - that the message is a resource-link launch;
   - the course role.

   The `state` can be used once, so a replayed launch is refused.
3. **Instructor launch:** the tool records which Moodle teacher opened which course and activity. It hands the browser a one-time claim that expires after 15 minutes. A signed-in platform teacher redeems the claim to be tied to that Moodle teacher account.
4. **Learner launch:** the exam is the one linked to this activity.
   - If the activity is not linked, nothing opens.
   - If the `exam_id` custom parameter disagrees with the link, nothing opens.
   - The student is matched as described in section 3, then enrolled in the linked exam only.
5. The browser is sent to `<app>/lti/launch` carrying a one-time ticket that expires after two minutes. The page trades it for a session as that student, then opens `/student/exams/<exam>`.
   - The ticket is in the URL fragment, so it never appears in server logs.
   - A ticket presented for a different exam is refused and burned.
6. Lockdown exams continue exactly as before: the student opens the exam browser from the exam page.

## Troubleshooting

| What the student sees | Cause |
| --- | --- |
| "This activity is not linked to an exam yet" | No teacher of the course has clicked **Link to this exam**. |
| "Your account is waiting for your teacher" | The Moodle ID number is empty or matches no roll number. Confirm the student on the **Moodle links** panel, or set the ID number in Moodle. |
| "This Moodle role cannot open the exam" / "Moodle did not say who you are in this course" | The user is not enrolled as a student or teacher in the course, or has both roles. |
| "This Moodle site is not registered" | The `lti_platforms` row is missing, or its issuer or client id differs from Moodle's configuration details. |
| "Moodle could not be verified" | The deployment id is not in `deployment_ids`, the server clock is wrong, or the keyset URL is wrong. |
| "Moodle did not answer in time" | Moodle's keyset URL did not respond within 5 seconds. |
| "This link cannot open that exam" | The `exam_id` custom parameter disagrees with the linked exam. |

| What a teacher sees | Cause |
| --- | --- |
| No activities on the **Moodle links** panel | Open the activity in Moodle as its teacher and click **Link my Moodle course**. |
| Grade missing in Moodle | `lti_grade_targets` shows `pending_score`, `post_attempts` and `last_error` for the student. A null `lineitem` means the activity does not accept grades: turn on **Accept grades from the tool** and set a maximum grade. |
